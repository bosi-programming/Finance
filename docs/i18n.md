# Languages

The app speaks English (`en`), Brazilian Portuguese (`pt-BR`) and Spanish (`es`), through `i18next` and `react-i18next`.

## How the app picks a language

- `resolveLanguage` in `src/i18n/languages.ts` reads `navigator.languages` in order and takes the first match on the base tag: `pt*` → `pt-BR`, `es*` → `es`, `en*` → `en`.
- No match → `en`.
- No picker, no storage. The language stays the same until the page reloads.
- `src/i18n/index.ts` sets `<html lang>` and the page title to the chosen language.

## Numbers and money

Each language has a number locale and a currency in `LOCALE_SETTINGS`:

| Language | Number locale | Currency | Example    |
| -------- | ------------- | -------- | ---------- |
| `en`     | `en-US`       | USD      | `$5,000`   |
| `pt-BR`  | `pt-BR`       | BRL      | `R$ 5.000` |
| `es`     | `es-ES`       | EUR      | `5000 €`   |

- The stored salary and budget values are plain numbers. The currency is only how the app shows them: it never converts, and the JSON export holds no currency.
- Inputs accept the format of the active language: `1,234.56` in `en`, `1.234,56` in `pt-BR` and `es`. The currency sign is optional and goes where the language puts it (`R$ 10`, `10 €`).
- `es-ES` does not group four-digit numbers (`5000 €`), so input also takes amounts with no grouping.
- Domain functions in `src/domain` take `LocaleSettings` as the last argument, defaulting to `en`. Components pass `useLocaleSettings()`.

## Adding or changing text

1. Add the key to `src/i18n/locales/en.ts`.
2. Add the same key to `pt-BR.ts` and `es.ts`. `tsc` fails if a key is missing or extra, and `locales.test.ts` fails if a `{{placeholder}}` differs from `en`.
3. In a component, call `t('area.key')` from `useTranslation()`. Outside React (the store), call `i18n.t` from `@/i18n`.

Domain validation returns translation keys, not text (`BudgetDraftErrors`, `salaryErrorKey`); the component translates them.

## Tests

- `src/test/setup.ts` switches to `en` before each test, so tests do not depend on the runner's language.
- To test another language, call `await i18n.changeLanguage('pt-BR')` in the test.
- Playwright runs with `locale: 'en-US'`.

## Not translated

- Budget names and categories are user data, so the app does not translate them. That includes categories from the legacy CLI import (`personal`, `business`, …).
