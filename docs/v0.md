# Finance FE v0 scope & non-goals

v0 is a local-first, browser-only budget tool. A single user enters a salary, manages fixed and percentage budgets, and sees an allocation breakdown. No setup, no account, no network.

## In scope

- Salary input on `/salary`.
- Fixed and percentage budget CRUD on `/budgets`.
- Allocation preview on `/result`.
- Validation: percentage sum > 100% -> error; fixed sum > salary -> warning; remaining amount shown in every state with a breakdown.
- Persistence via `localStorage`.
- JSON export/import for backup and migration.
- Import from the existing CLI export, mapping CLI groups to app budgets.
- Three routes: `/salary`, `/budgets`, `/result`.
- Top-level navigation across all routes.

## Out of scope

- Backend, API, server-side storage.
- Authentication, accounts, multi-user.
- Cloud sync or multi-device support.
- Analytics, reporting, charts.
- Recurring / scheduled budgets.
- Currency conversion or multi-currency.
- Offline/PWA, installable app, mobile native.
- Advanced budget rules beyond fixed/percentage.
- Real-time collaboration.
- Implementation details covered by design/eng tickets.

## Persistence & privacy

- Data lives in `localStorage` only.
- JSON file is the only backup/migration path.
- No data leaves the browser.

## Architecture

- React 19, TypeScript 5.9, Vite 7, TailwindCSS 4.
- `bosi-design-system` for UI.
- React Router v7 for routing.
- Zustand for state.
- Vitest, React Testing Library, Playwright for testing.

## CLI migration

- Import accepts a JSON export derived from the existing CLI tool.
- CLI fixed groups map to fixed budgets:
  - `CONTAS_PESSOAIS` -> personal
  - `CONTAS_DA_EMPRESA` -> business
  - `ASSINATURAS` -> subscriptions
  - `INVESTIMENTOS_FIXOS` -> fixed investments
- CLI percentage groups map to percentage budgets:
  - `INVESTIMENTOS` -> investments
  - `LAZER` -> leisure
- Each group becomes budgets with user-defined categories.
- User can re-categorize during import or later.
- Exact JSON shape and localStorage schema are documented in `data-schema.md`.
